# D2A hard-limited build implementation

This is a proposed hosted-runner-only implementation. None of its privileged setup has run on HP or any runner during preparation.

- GitHub-hosted Ubuntu 22.04 x86_64 only. No self-hosted fallback. Read-only GitHub token, no persisted checkout credential or production secrets.
- Public dependencies are installed/acquired first; exact upstream/dependency IDs, pristine archive hashes and build-control hashes verified. Acquisition has a separate receipt, explicitly NOT_APPLICABLE_ACQUISITION_ONLY for native resource enforcement. It cannot configure/build. A fresh directory collision stops it.
- Root supervisor executes only in a private mount namespace. Minimum admission: 2 logical CPUs, 6GiB MemAvailable, 18GiB free disk; actual cgroup limit/current headroom also admitted below. No host kernel/sysctl/host-CNI modifications.
- Reserve a 12GiB regular file using fallocate and verify allocated blocks, then create/mount ext4 inside the private namespace. This is a hard capacity budget, not a du/df monitor. Scratch data includes extracted source, build objects, TMPDIR/HOME and all worker logs. Native worker root filesystem is read-only except /work; private /dev is in-memory and covered by the memory cap. Scratch file contents cannot spill to a writable host directory.
- Transient exact UUID systemd unit: MemoryMax=6GiB, MemorySwapMax=0, CPUQuota=200%, CPUQuotaPeriodSec=100ms, TasksMax=256, RuntimeMaxSec=4500s, KillMode=control-group, OOMPolicy=kill and NoNewPrivileges=yes. No delegation or rights to move processes out of the cgroup. Two compiler jobs maximum for both selected target graphs.
- Because systemd's manager does not inherit a client's mount namespace, the unit explicitly nsenters the live supervisor's private mount namespace before bwrap creates the worker's new namespaces. It never joins/changes production networking. bwrap drops to the original runner UID/GID, drops all capabilities, clears the entire environment and mounts /proc read-only. Workers cannot invoke sudo successfully under NoNewPrivileges.
- Before configuration, worker independently reads memory.max, memory.swap.max, cpu.max, pids.max; verifies cgroup v2, memory.peak, pids.peak, cpu.stat/events; verifies UID, zero effective/permitted/inheritable/bounding/ambient capabilities and NoNewPrivs; verifies new mount/net namespace inodes, only lo/no external routes, all writable mounts bounded and ext4 capacity. Any missing/inexact readback blocks. This includes older kernels lacking pids.peak.
- External supervisor samples disk consumption and reads kernel peak memory/PID/CPU usage counters. Final accounting requires the cgroup still exists: stale earlier samples cannot substitute for final kernel accounting. Disk high-water is explicitly a 100ms sampled lower bound, not an exact kernel peak. Final disk consumption/capacity are separately recorded; exact transient disk high-water is unsupported.
- Each build command has its own process group. Phase timeout/nonzero/error records a receipt; TERM then KILL cleanup applies to that group. External supervisor kills the exact unit's entire cgroup, including escaped process groups, and requires populated=0. CPU quota, memory/PID/storage caps and unit runtime deadline are independent of the worker's Python monitor.
- Outer workflow timeout: 77m command +15s kill grace, 80m step, 100m job. Unit's 75m deadline and 10s systemd stop deadline remain even if external Python dies. SIGTERM/SIGINT are handled for best-effort finalization; SIGKILL or runner destruction can prevent it. No guarantee of final receipt or upload in that case: missing evidence is INCOMPLETE.
- Native logs capped at 64MiB per file and copied evidence at 256MiB per run. Over-budget logs trigger termination/BLOCKED; oversized/missing diagnostics prevent PASS. A runner teardown reclaims retained private scratch images; they are not uploaded as deployable binaries.

Actual cgroup/namespace/loop-mount/kernel/runner compatibility, resource usage and cleanup are NOT VERIFIED by mocks. Future execution must fail closed if unsupported. No alternative VM/cluster, weaker quota or unisolated build is selected automatically.

Host IPC defense: the sandbox is built from an empty root, with only toolchain/system-library/configuration/sysfs read-only binds, a read-only reviewed /repo and /sources, and bounded /work. Host /run, /var, /tmp and home directories are not bound; their sandbox counterparts are empty/read-only. The worker verifies this plus absence of socket nodes in bound inputs. This avoids treating a read-only host Docker/DBus socket as network isolation. Package-version metadata is collected separately by the supervisor and supplied as a regular file.

Before offline entry, acquisition freezes installed package versions and SHA-256 of toolchain/header/library/data files under the standard /usr roots plus compiler alternatives/loader configuration. The worker revalidates the exact file set, content/symlinks and package-version snapshot before configuration. /usr/local is hidden, preventing an unrecorded local-prefix dependency fallback. This scan is bounded to 200,000 files and 24GiB; exceeding the bound blocks rather than silently omitting inputs. It is proposed runner behavior only: no HP /usr scan was run. OS packages are resolved from signed apt metadata on the future hosted runner, then frozen for that run; no claim of an immutable preapproved OS image or independently archived .deb set is made.
