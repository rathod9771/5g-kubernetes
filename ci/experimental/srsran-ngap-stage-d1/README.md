This package implements a native CU-CP driver and read-only local snapshot observer plus a separately gated namespace launcher, AMF/NRF configs, independent packet/log projection, offline assessment and a **native-build-only workflow proposal**. No NGAP/NF/harness binary, SCTP socket, namespace, NF or CI workflow has been executed in Stage D1. Do not run this package on HP or the existing Kubernetes cluster.

## Source changes and construction

`activation.patch` is the exact D0 four-file proposal, applied only in the disposable source tree created for D1. Internal CU implementation/controller constructor overloads supply the existing snapshot config. Normal constructors and the public factory remain default-off. No Stage A file, protocol procedure, original instrumentation patch, test-clock definition, production CLI or scenario profile is modified.

`runtime_driver.cpp` constructs the actual `cu_cp_impl`, a real `n2_connection_client_config::network`/SCTP gateway, IO broker, serialized CU task worker and real timer source. It does not instantiate a mock AMF, no_core mode, fake setup response or standalone snapshot source. Configuration is explicit and synthetic: CU127.0.0.10 → AMF127.0.0.20:SCTP38412, PLMN00101/TAC7/SST1, AMF index0/name l3-d0-amf-01. No DU, CU-UP, UE or RF is required. One AMF only; the approved community initial setup path is not a multi-AMF runtime implementation.

The native driver takes an explicit execute-isolated gate, original host network-namespace inode, duration and exclusive output path. It refuses UID0, the host namespace or a non-loopback interface inventory. This is defense in depth: the launcher provides full namespace/route/cgroup/capture verification. Native `start()` runs on an outer thread because it blocks on a promise; snapshots are requested/inspected only outside the CU executor. PRE_START, OBSERVE and AFTER_STOP are recorded. The driver does not grade protocol accuracy and emits `D1_DRIVER_COMPLETED_NO_PROTOCOL_VERDICT` only on its normal completion path.

The observer keeps one outstanding ticket, waits with bounded sleeps off the owner executor, preserves original <=10ms publication and <=30s inspection-age rules, and records immutable incarnation, NF/peer identity, validity/completeness, per-peer state/reason, generation, sequence, revision and producer/observer timestamps. Invalid or unavailable tickets remain UNKNOWN; unknown transitions are null. One ticket may remain retained until stop for invalidation testing; no request is made after stop/destruction. Exclusive no-follow file creation, parent ownership/mode checks, <=5000 records, <=8MiB total, <=8KiB records and final fsync bound the local writer. No monitoring listener or subscriber/NAS fields exist.

## AMF dependency assessment

Open5GS source is independently checked out at the exact user-approved commit. Source anchors:

- `src/amf/init.c::amf_initialize`: parse local/SBI/metrics/NF config, open SBI, then NGAP listener and AMF event thread.
- `lib/sbi/context.c::ogs_sbi_context_validation`: AMF requires an SBI server and an NRF or SCP client under the default delegation policy; no-client configuration is rejected.
- `src/amf/context.c::amf_context_validation`: NGAP address, GUAMI, served TAI, PLMN/slice support, AMF name, security algorithm lists and valid T3512 are mandatory.
- `src/amf/ngap-sctp.c::ngap_server`: Linux SOCK_STREAM SCTP listener. `lib/sctp/meson.build` uses Linux SCTP on this platform.
- `src/amf/ngap-handler.c::ngap_handle_ng_setup_request`: validates foreign PLMN, TAI and slice, sends explicit failure or NGSetupResponse; `ngap-build.c` copies configured AMF Name into the actual response.
- `src/nrf/init.c`, `src/nrf/app.c`: independent NRF SBI startup. `src/main.c` handles SIGTERM/SIGINT; AMF shutdown closes NGAP/SBI with the existing holding timer.
- No database initialization occurs in these AMF/NRF entry paths. A MongoDB process/subscriber database is not part of this NG Setup experiment. `lib/dbi/meson.build` still requires Mongo C development libraries during full-project configuration; build dependencies are different from running a database service.

Selected source-backed minimal arrangement: **AMF + NRF**, not the bundled full-core entrypoint and not an unverified clientless AMF. Runtime initialization/interoperability is still UNVERIFIED until native execution. Synthetic `amf.yaml` and `nrf.yaml` agree on identity/PLMN/TAC/slice. `amf-reject.yaml` intentionally serves TAC8 while CU requests TAC7: same peer/name and PLMN, explicit source-backed TAI rejection path. AMF startup performs its normal SBI registration/subscription/update/deregistration requests to the isolated NRF (including PUT/POST/PATCH/DELETE as applicable). These are local disposable NF state changes requiring the future runtime approval, not production GET-only monitoring and not OSM operations. No production configurations, MongoDB volumes, credentials, subscribers, WebUI, TUN, SMF, UPF, AUSF or UDM are reused/launched. No metrics server is configured; the inspected metrics parser only adds servers from configured entries.

The approved Open5GS source has mutable wrap refs for freeDiameter/libtins/prometheus-client-c/usrsctp. `dependency-lock.PROPOSED.json` resolves them to immutable public commits for separate review; these new dependency selections have NOT been compiled or compatibility-tested. Future build supplies exact checkouts and `--wrap-mode=nodownload`; missing/unreviewed dependencies fail rather than silently using newer refs. No container image is assumed or selected.

## Isolation, approval and runtime limits

`runtime_launcher.py` is inert on import and refuses execution without an explicit, unexpired one-use runtime approval. **No real approval file is supplied or generated by D1.** Approval binds scope/nonce, exact source IDs, source-manifest hash, package SHA256SUMS hash, reviewed binary paths/hashes, test ID, operator attribution and duration. <=900-second window with >=180 seconds remaining required. Existing output directory/consumption record collides and stops; no reuse/deletion/retry/renewal. Fields are a separately reviewed local authorization record, not a cryptographic attestation.

Future execution requires a fresh GitHub-hosted runner, package staged in owner-protected RUNNER_TEMP, new network namespace and **no veth, host networking or external route**. Before loopback activation and the three fixed /32 loopback address additions, verify inode differs from the original host and that only lo exists. Full IPv4/IPv6 route/link checks and confirmation of all three addresses follow; any non-loopback address blocks. AF_PACKET capture and SCTP socket creation, pidfd support, cgroup-v2 CPU/memory limits and tools/resources must pass before starting NFs. No modprobe, sysctl, networking installation or compatibility fallback is implemented. Failures are BLOCKED.

Setup/capture helper only runs privileged on the disposable runner; NFs/driver and packet decoder drop to the original non-root UID/GID, with no_new_privs for NFs/decoder and no inherited production environment. Every child namespace is checked. Exact child pidfds are used for cleanup, never names or existing services. Forced cleanup or unexpected child exit makes the run incomplete. Package/binary hashes are checked again after runtime.

Required runtime cgroup limits: memory.max <=2GiB and cpu.max <=2 CPU equivalents; they must actually exist or admission fails. No hard memory enforcement is claimed as tested. Build admission >=2 logical CPUs, >=5GiB effective available RAM, >=15GiB free disk; <=2 compiler jobs. Runtime admission requires >=1GiB effective cgroup memory headroom, >=2GiB physical available RAM, >=2 logical CPUs and >=128MiB disk; checks run only on the future runner, not HP. Driver <=120s; launcher reserves time for decoding within a 170s local deadline. A separately reviewed **180s outer watchdog plus <=10s cleanup** remains mandatory for blocked native start/stop/syscalls. Resource budgets are estimates, not measured runtime peaks.

## Independent evidence and judgment

Packet evidence is collected by tcpdump in the new namespace before AMF/CU start: lo only, fixed N2 endpoints/SCTP38412, no promiscuous mode, <=2048 packets and snaplen2048. Early capture termination is a hard failure. Raw PCAP stays private and is not eligible for automatic publication. TShark field inventory is checked at runtime; PDML is held in a bounded anonymous temporary file (<=32MiB), not exported. Decoder requires actual NGSetup Request/Response/Failure fields, procedure21, socket direction/ports, association index, expected AMF name and synthetic PLMN bytes. Unrelated/undecoded NGAP or SCTP DATA, ambiguous identities and malformed/truncated evidence fail closed. Installed-version compatibility is still UNVERIFIED.

Field definitions: [Wireshark NGAP reference](https://www.wireshark.org/docs/dfref/n/ngap.html) and [SCTP reference](https://www.wireshark.org/docs/dfref/s/sctp.html). They support field selection, not any claim that a packet was collected. Independent decoder code does not read snapshots. SCTP chunk types and association IDs are retained as transport evidence, never renamed application health. CU/AMF/NRF raw log lines are streamed through a bounded allowlist; only marker/source/PID/receipt timestamps survive, never arbitrary log text, subscriber fields or payloads.

`assess.py` requires decoded setup, independent startup/acceptance log markers, exact peer binding, fresh snapshot identity and compatible association/time windows. SCTP-only evidence never qualifies NG Setup. A later planned shutdown does not invalidate earlier UP evidence; a disconnect before the candidate observation does. Multiple associations require the separate reconnect protocol, not blind reuse of first-setup rules. Top-level genuine verdicts require completed execution and timing evidence; synthetic fixtures remain NOT_ASSESSED.

Wall/monotonic anchors and producer/observer timestamp pairs provide an **empirical same-kernel consistency envelope**, including capture quantization allowance; >100ms inconsistency gives unknown timing. This is not absolute clock synchronization proof or a bound against unobserved clock steps. No Tdet or MTTR is calculated. `normalize()` emits generic-schema NOT_ASSESSED evidence only; it cannot assign PASS to a snapshot by itself. Final aggregate evaluation remains separate from native driver completion. `postprocess.py` verifies the private evidence hash inventory and exact package/source provenance before separate offline assessment and generic-schema normalization. It never accepts labelled synthetic evidence as a genuine run. No production assurance journal is opened.
