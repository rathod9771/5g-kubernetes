# P8 researcher onboarding and initial deployment

## Implementation and evidence boundaries

The prebuilt OCI pipeline requires no BuildKit, Skopeo or registry write access.
It verifies registry manifest/config/layer bytes, then uses existing Helm lint,
render, packaging and immutable release storage. Supply a chart below the
operator-approved tenant workspace; registration never edits backend.py.
Dockerfile builds and authenticated publication retain the P7 path unchanged.

InitialDeployment is a separate create-only adapter. Catalog publication and
initial instantiation have independent request/approval records. It uses the
existing verified-HTTPS Catalog transport and the combined OSM endpoint already
used by ran-selector/osm_client.py: POST /nslcm/v1/ns_instances_content. The nf/nf
namespace parameters follow the existing installer KDU payload. This is source-
compatible implementation, OFFLINE_TESTED, not LIVE_VERIFIED on this OSM v19.
There is no upgrade, rollback, automatic termination, repair or reconciliation.
Lifecycle.execute continues to reject updates. OSM CLI/osm_im is not required.

Independent reviewer approval binds exact request and target policy for 300s.
Builder requests, reviewer approves, operator submits. Project must be research-
<tenant>, with non-default non-admin scoped credentials. Enabled catalog and
namespace targets are server-only. Namespace UID, kube-system UID, VIM UUID and
telecom.research/tenant label are checked. Existing pods or workload controllers block first submission.
A shared nonblocking lifecycle lock and durable namespace reservation prevent
concurrent/repeated initial submissions. Pending or unknown OSM operation states
block creation. Catalog bytes/UUIDs are read back immediately before submission.
SUBMITTING is committed before the one create request. Timeout, malformed result,
transport errors and protected IDs become UNKNOWN_OUTCOME, never automatic retry.
A process crash after intent also requires manual operator reconciliation.

Explicit one-shot status refresh checks NS/operation identities, INSTANTIATE,
COMPLETED, READY/running/configured, namespace identity, pod readiness and exact
imageID digest. WORKLOAD_READY is not application or telecom qualification.
Application health is UNVERIFIED; protocol tests NOT_RUN; production_eligible is
always false. Missing status is UNAVAILABLE, not healthy. Dashboard observations
age to STALE after 120s. No continuous poller or deployment worker is started.
Requests use existing bounded Catalog transport (30s,16MiB response per request),
read-only kubectl (5s API/7s process,2MiB output per call,256MiB tree watchdog).
No network retries. A complete submission has bounded sequential requests,
not a single end-to-end deadline. See limitations before external exposure.

## Researcher walkthrough

1. Operator provisions a private workspace/runtime/auth/policy and allowlists
   OCI repository and chart source. Supply token by header, never URL or logs.
2. POST /api/telecom/workloads {manifest,event_id}. For OCI source, source and
   image must have the same immutable digest. Provider capability declarations
   are not verified 3GPP evidence. Correct roles/interfaces/PLMN/TAC/slices/DNNs.
3. POST /pipeline-jobs {workload_id,chart,image_mode:"prebuilt",event_id}; chart is
   relative to the configured tenant source root. OCI source uses local chart.
4. POST /pipeline-runs {job_id}, or explicit foreground worker CLI for a long job.
   Successful completion validates configuration/chart, verifies image bytes and
   packages Helm/KNF/NSD. Failed stages block release/promotion. Inspect release.
   Browser requests time out at 15s: inspect job state before manual action; do
   not blindly resubmit uncertain jobs. No automatic UI retries.
5. POST /publication-requests {release_id,action:"catalog",event_id}.
6. Independent reviewer POST /publication-approvals {request_id,event_id};
   publisher POST /catalog-publications {request_id,approval_id}. New immutable
   names only; never overwrite production entries. Separate approval needed live.
7. POST /deployment-requests {publication_id,event_id}. Independent reviewer POST
   /deployment-approvals {request_id,event_id}. Operator POST /initial-deployments
   {request_id,approval_id}; this is a separate explicitly approved initial NS.
8. Operator POST /deployment-observations {request_id,event_id}; GET /deployments,
   /pipeline-jobs, /releases and /publication-requests display durable history.
   No arbitrary instance IDs, namespace, credentials or evidence in request JSON.

Use /api/telecom prefix for every API above. JSON endpoints reject unknown fields.
Roles are tenant scoped; object listing is within tenant; workload requests use
owner checks; privileged reviewer/operator may act within their assigned tenant.
Unauthenticated mutations and cross-tenant references fail closed. Legacy
operator pages and safeguards remain registered; production activation is not
performed in P8. See P8-LIVE-TEST.md for separate approval gates.

## Research-only installation experience

Run the non-mutating installer plan:

    PYTHONPATH=scripts python3 -m telecom.research_setup --mode research-only --reuse-existing --plan

This is PLAN_ONLY, not a greenfield infrastructure installer. Do not run install.sh
for research-only onboarding: the legacy installer deploys reference workloads.
Reuse existing Kubernetes/Rancher/OSM/Prometheus/Grafana endpoints. Prerequisites:
Python3, Flask, PyYAML, Git, real Helm, kubectl for approved deployment verification,
trusted CA, tenant-scoped RBAC/OSM credentials, private auth/policy files, owned
runtime/workspace. Prebuilt mode needs registry pull permission/verified TLS,
not build workers or registry write credentials. Dependencies missing on a new
machine require an approved installation; no automatic package installation.

Set TELECOM_AUTH_FILE, TELECOM_EXECUTION_POLICY, TELECOM_RUNTIME_DIR,
TELECOM_WORKSPACE and HELM_BIN=/usr/local/bin/helm.real. Token file contains only
SHA256 token hashes, subject, tenant, roles; files0600/directories0700. Policy
sections and private secret references follow P5/P7. Never copy admin kubeconfig.
Start the existing research-only launcher manually in foreground:

    python3 docs/telecom/p6/research_only.py --port 5099

Binds loopback only, no reloader, no production backend import/service restart.
Use an authenticated TLS reverse proxy for remote exposure, separately reviewed.
Do not expose Flask development server directly. Stop with Ctrl-C; preserve
private journal and artifacts. Remove only this explicitly created private
runtime/workspace after archival and approval. Uninstall.sh is not a research
cleanup tool: do not terminate reference services. Deleting any live test NS,
catalog package, namespace or project requires separate identity-checked cleanup
approval and must be performed through the appropriate lifecycle owner, OSM.

## Remaining limitations and security review

No real OSM create, namespace placement, project RBAC, registry pull or health
has been validated. Namespace must be separately provisioned; workload-only
service account needs namespace reads and namespace-scoped pod/controller reads. OSM must
have isolated VIM/K8s placement and scoped project role; never use admin. The
current namespace UID verification additionally needs read access to kube-system
metadata, not secrets, exec, mutation or whole-cluster workloads.

P8 accepts only a private, bounded JSON kubeconfig with one context/cluster/user,
embedded CA and static token or embedded client certificate/key. Exec/auth-provider,
proxy, insecure TLS, external credential paths and unknown top-level keys are
rejected; kubectl receives a frozen private copy. No tenant-supplied config is
accepted. Static RBAC still requires separate verification. Initial packages must
have namespace_portable=true: no rendered explicit namespace or non-ClusterIP
Service; old packages must be rebuilt and catalog-approved before deployment. Exact
OSM nsd-id/status field shapes and imageID digest representation must be checked
in the disposable test; mismatches fail closed. Kubernetes Ready is readiness
probe evidence only, not independent application/protocol health. Live NF charts
requiring privileged networking, CRDs, secrets, hardware or advanced kinds remain
outside the constrained chart validator. No automatic recovery for uncertain
create. No live project creation or validation is claimed.

Real builds need off-host mTLS BuildKit + attested quotas/worker identity/lease,
buildctl, authenticated TLS research registry and Skopeo with reviewed debug
request accounting (P7). Prebuilt images bypass build/push prerequisites.
Running-instance updates/rollback remain NOT_VERIFIED and non-executable.
Deployment history retains 64 transitions, then fails closed for operator retention
review. Registry prebuilt verification uses direct HTTPS and a scoped bearer token
where configured; registry-specific token acquisition is an operator prerequisite.
Private-image pull credentials must also be provisioned separately in the isolated
namespace; registry verification permission alone does not authorize Kubernetes pulls.
